# 测试、代码审查与安全

## 风险驱动测试

根据失败成本分配测试，而不是追求单一覆盖率数字。

### 单元测试

- 业务规则、边界值、舍入、时间、状态机、权限决策。
- 一个测试表达一个行为；失败信息能指出哪条规则被破坏。
- 外部 I/O 不应进入纯单元测试；不要把所有对象都 Mock 到只验证调用次数。

### Spring 切片测试

- Web 层：路由、绑定、校验、序列化、鉴权和错误映射。
- 数据层：实体映射、查询、约束、分页、锁和方言相关行为。
- 只加载相关切片；如果行为依赖真实容器/过滤器，选择运行服务器的集成测试。

### 集成与契约测试

- 事务、数据库、消息、缓存和第三方协议使用与生产语义接近的替身或容器。
- 对外契约测试覆盖字段兼容、错误语义、超时与重试边界。
- 集成测试隔离数据并可重复运行；不依赖执行顺序。

### 回归测试

- 先让测试在修复前失败，确认它确实覆盖缺陷。
- 至少加入一个触发样例和一个关键相邻边界。
- 并发缺陷使用协调原语、重复压力或模型化断言，不靠长时间 `sleep` 赌调度。

## 代码审查严重度

- **阻断**：可导致数据损坏、越权、密钥泄露、远程执行、大面积不可用。
- **高**：在合理条件下产生错误结果、事务不一致、兼容中断、死锁或资源耗尽。
- **中**：可维护性或性能问题已具备明确触发路径，但影响有限或有替代保护。
- **建议**：非必需改进；不得伪装成正确性缺陷。

每条发现包含：

```text
标题与严重度：
位置：
触发条件：
影响：
证据：
修复方向：
```

## Java/Spring 审查清单

- 空值、边界、溢出、精度、时区、字符集与 Locale。
- `equals/hashCode/compareTo` 一致性，可变对象作为 Map key。
- 资源关闭、中断恢复、线程安全、锁顺序、共享可变状态。
- 事务代理、自调用、传播/隔离、异常回滚和外部副作用。
- ORM N+1、懒加载越界、无界查询、错误级联、批量处理。
- HTTP 超时、重试放大、连接池、幂等、错误映射。
- 日志敏感信息、异常吞噬、过量高基数标签。
- 配置默认值、feature flag 双路径、升级/回滚兼容。

## 安全基线

### 输入与输出

- 在信任边界做类型、长度、范围、格式和业务合法性校验。
- SQL/JPQL 使用参数绑定；系统命令使用结构化 API，避免拼接。
- HTML、JSON、CSV、日志等按目标上下文编码，不能用一次“通用清洗”替代。
- 文件路径规范化后限制在允许根目录；上传限制大小、类型、数量并隔离存储。

### 身份与权限

- 认证证明“是谁”，授权判断“能做什么”；每个对象访问需服务器端校验。
- 管理接口、Actuator、调试端点和错误页同样纳入保护。
- 会话/令牌设置过期、撤销和最小范围；不得写入普通日志。

### 数据与序列化

- 避免反序列化不可信 Java 原生序列化数据。
- XML 若不需要 DTD 则禁用，并限制外部实体和外部协议访问。
- 敏感字段按必要性收集、最小化返回、传输加密、存储保护并设保留周期。
- 密码使用专用自适应哈希方案；不要自制加密或硬编码密钥。

### 依赖与供应链

- 使用锁定/依赖管理和可复现构建；记录直接与传递依赖。
- SCA 结果需确认组件、版本、可达性和修复版本；抑制项要有负责人、原因和期限。
- 升级修复需运行兼容测试，不能只以扫描变绿作为完成。
- 插件、构建脚本和下载物同样属于供应链边界。

## 交付门槛

- 行为与验收条件一致。
- 有与风险匹配的自动化测试或明确的未覆盖说明。
- 构建、测试、静态检查命令及退出结果已记录。
- 安全、数据、兼容、性能和回滚影响已审查。
- 不含凭据、临时调试、无关格式化或意外生成文件。
