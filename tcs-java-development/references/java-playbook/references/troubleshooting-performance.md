# 故障诊断与性能优化

## 诊断契约

先问清：症状是什么、影响谁、何时开始、变化趋势、最近变更、当前缓解措施。若线上操作可能扩大影响，先给只读检查和回滚条件。

## 证据链

1. **定义指标**：错误率、P50/P95/P99、吞吐、队列长度、饱和度、受影响请求或租户。
2. **确定时间线**：首次出现、峰值、恢复、发布/配置/流量/依赖事件。
3. **分层定位**：入口、应用线程、JVM、数据库、缓存、消息、下游、主机/容器。
4. **形成假设**：每个假设必须能预测一条可观察结果。
5. **验证与排除**：用日志、指标、trace、profile、dump、SQL 计划或最小复现验证。
6. **修复与防复发**：短期止血、根因修复、回归测试、监控和操作手册。

## 常见信号

### CPU 高

- 区分应用计算、GC、锁自旋、序列化、正则、加解密和内核/网络开销。
- 采样 profile 或 JFR 优先于只看单次线程快照。
- 检查流量与输入规模变化，避免把容量问题误判为代码回归。

### 内存与 GC

- 区分泄漏、缓存/队列无界、突发分配、堆外内存和容器限制。
- 观察 GC 暂停、频率、分配率、老年代趋势和 OOM 类型。
- 堆转储可能包含敏感数据；采集、传输和保存需受控。
- 调大堆只是容量调整，不等于修复泄漏。

### 线程与锁

- 多次线程快照比较持续阻塞关系；单次快照只是一刻状态。
- 检查线程池 active/queue/rejection、任务耗时、下游超时和锁顺序。
- 恢复中断状态，避免无限等待；阻塞任务不要占用不合适的公共池。

### 数据库

- 以慢 SQL、执行计划、扫描行数、返回行数、锁等待、连接池饱和和事务时长为证据。
- 索引建议必须结合真实查询谓词和数据分布。
- 连接池调大可能把瓶颈推向数据库；先确认服务端容量和并发模型。

### 远程依赖

- 分解 DNS、连接、TLS、首字节、读取和重试耗时。
- 检查超时层级是否递减，重试是否叠加，熔断/限流是否真正降低压力。
- 对非幂等请求不自动重试，除非有可靠去重机制。

## 故障交付格式

- 影响与时间线
- 已确认事实
- 根因与证据
- 已排除假设
- 临时缓解与风险
- 永久修复与验证
- 防复发监控/测试
- 尚缺证据
