# 部署交付 Playbook（Phase 5）

## 平台选择

| 平台 | 适用 | 优势 | 限制 / 注意 |
|------|------|------|------------|
| Vercel | Next.js / 前端框架 + Serverless Functions | 零配置、预览部署、边缘网络 | Serverless 函数有冷启动与执行时长限制；商用需注意配额 |
| Netlify | 静态站、Jamstack、表单与函数 | 简洁、分支预览、重定向规则 | 构建分钟数限制；SSR 支持有限 |
| Cloudflare Pages | 静态站 + Workers / Functions | 全球边缘、免费额度高、WAF | 需理解 Workers 运行时差异 |
| VPS / 自托管（Nginx + Node/Docker） | 需常驻服务、自定义中间件、数据落地本机 | 完全可控、成本低 | 需自行负责安全加固、HTTPS 续期、监控与备份 |
| 静态导出（GitHub Pages / 对象存储） | 纯静态站 | 极简、成本低 | 无 SSR、无服务端 API |

选型给对比与推荐结论，并说明「为什么不选另一个」。

## 部署步骤（标注每步验证方式与常见失败原因）

1. **本地构建验证** — `npm run build` 必须本地先通过
   - 验证：构建产物目录存在、无警告级错误
   - 常见失败：依赖版本漂移（锁定 lockfile）、Node 版本不匹配（指定 engines / `.nvmrc`）、环境变量缺失
2. **配置环境变量** — 在平台面板或 `.env` 注入
   - 验证：构建/运行时日志无 `undefined` 配置；敏感值用密文存储
   - 常见失败：客户端前缀变量（如 `NEXT_PUBLIC_`）暴露密钥；构建期变量与运行期变量混淆
3. **绑定域名与 DNS** — 按平台要求加 CNAME / A / ALIAS 记录
   - 验证：`dig <domain>` 确认解析生效；注意 TTL 与解析传播延迟
   - 常见失败：根域名不能加 CNAME（用 ALIAS/ANAME 或 A 记录）；已有记录冲突
4. **申请 HTTPS 证书** — 平台自动签发或自备（Let's Encrypt）
   - 验证：浏览器无证书告警、HTTP 自动跳转 HTTPS
   - 常见失败：DNS 未生效导致签发失败；混合内容（页面引用 http 资源）
5. **上线验证** — 首页可访问、关键路径走通、无控制台报错、SEO 与 OG 标签生效
   - 验证：移动端与桌面端各测一遍；检查 404 与重定向规则

## 部署检查清单

- [ ] 构建命令与输出目录配置正确
- [ ] Node / 运行时版本与本地一致
- [ ] 环境变量齐全且敏感值不进仓库、不进客户端
- [ ] `robots.txt` / `sitemap.xml` 已上线且非 `noindex`
- [ ] 404 页面存在，旧 URL 有重定向规则（保 SEO）
- [ ] 缓存策略：静态资源带哈希长缓存，HTML 不缓存或短缓存
- [ ] 监控与告警已接（可用性、错误率、Core Web Vitals）
- [ ] 回滚方案明确：上一版本可一键回退，静态站保留历史产物

## 回滚与验证步骤

```
触发条件：错误率突增 / 关键路径不可用 / 核心指标严重劣化
回滚动作：<平台上一版本回退> 或 <重新部署上一个已知良好产物>
回滚后验证：首页 200、关键路径走通、控制台无报错、监控指标恢复基线
事后：定位根因 → 修复 → 补自动化检查（构建门禁 / 冒烟测试）防复发
```

涉及用户生产环境的操作（改 DNS、推送部署、改生产环境变量）**先给影响评估再实施**，并保留回滚窗口。
