# 全栈应用开发工作流

从需求澄清到生产加固的一站式交付方法论。核心主张：**架构决策先于代码，基础设施先于业务，验证通过才算完成**。

## 何时使用

命中以下任一即进入本工作流：

- 新建一个包含后端服务 + 前端界面 + 数据存储的应用
- 设计并落地 REST / GraphQL / tRPC / gRPC 接口
- 实现登录认证、令牌刷新、权限控制（RBAC）
- 前后端对接：API 客户端、跨端类型安全、CORS、错误与加载态
- 引入文件上传、后台任务、缓存
- 引入实时能力：轮询 / SSE / WebSocket
- 上线前加固：健康检查、优雅停机、安全头、限流

**不适用**：纯前端视觉/交互调整；脱离后端语境的表结构设计；单文件小修小改。

## 六阶段工作流

### Phase 0：需求澄清（六问，用户已给则跳过）

开工前必须明确，缺项先问再动手：

| # | 维度 | 典型取值 |
|---|------|---------|
| 1 | 技术栈 | Express+React / Django+Vue / Go+HTMX / Next.js 全栈 |
| 2 | 服务形态 | 纯 API / 全栈单体 / 微服务 |
| 3 | 数据库 | PostgreSQL / MySQL / SQLite / MongoDB，缓存 Redis |
| 4 | 接口方式 | REST / GraphQL / tRPC / gRPC |
| 5 | 实时能力 | 不需要 / 轮询 / SSE / WebSocket |
| 6 | 认证 | 不需要 / JWT / Session / OAuth / 第三方（Supabase 等） |

### Phase 1：架构决策（写代码前先声明）

逐个给出决策，每个**一句话说明理由**，向用户简要确认后再进入实现：

1. 项目结构 —— 默认按功能（feature）组织，而非按技术层平铺
2. API 客户端方案 —— 类型化 fetch 封装 / React Query / tRPC / OpenAPI 生成
3. 认证策略 —— 访问令牌时效、刷新令牌存放位置、RBAC 粒度
4. 实时方案 —— 按「数据更新频率 + 方向性 + 复杂度」选型
5. 错误处理方式 —— 类型化错误类 + 全局处理器 + 统一响应结构

### Phase 2：脚手架与基础设施

落地骨架与横切设施，产出 `.env.example`（仅占位值）。逐项清单见 `references/scaffolding-checklist.md`。

关键项：集中配置并在启动校验（快速失败）、类型化错误体系、全局错误中间件、结构化 JSON 日志贯穿请求 ID、数据库迁移 + 连接池、边界输入校验、认证中间件、`/health` 与 `/ready`、优雅停机、CORS 显式来源、安全头。

### Phase 3：核心实现（三层分离）

- **控制器**：解析请求 → 调服务 → 格式化响应。**不写业务逻辑**。
- **服务层**：承载业务规则与编排，多步写入进事务。**不依赖 req/res 等 HTTP 类型**。
- **仓储层**：数据查询与外部调用，避免 N+1。
- 后台任务与缓存按需引入：任务幂等 + 重试 + 死信；缓存必设 TTL + 写后失效。

每完成一个模块立即做一次编译检查，不要攒到最后。

### Phase 4：前后端集成与实时能力

搭建 API 客户端（Base URL 走环境变量、令牌自动附加）、加载态与错误态、后端错误映射为可读文案。按需接入实时能力（含心跳与断线重连）。实现细节见 `references/auth-and-integration.md` 与 `references/realtime-and-hardening.md`。

交付前用 Grep 自检：是否存在硬编码 URL、占位错误提示（"出错了"）、缺失加载态。

### Phase 5：验证与交付（四步，顺序不可跳过）

1. **编译** —— 后端与前端均无编译错误
2. **启动冒烟** —— 启动服务后用 Bash + curl 验证关键端点返回正确
3. **集成** —— 前端可连通后端（CORS、API 地址、认证流程走通）
4. **实时**（如适用）—— 双标签页验证数据同步

四步通过后输出交付总结。检查清单与模板见 `references/testing-and-delivery.md`。

## 硬规则（不可违反）

1. **分层边界** —— 控制器无业务逻辑；服务层不 import HTTP 类型；跨层通过依赖注入解耦。
2. **配置集中** —— 全部来自环境变量并在启动时校验；**密钥绝不硬编码、绝不进版本库**；只提交 `.env.example`，`.env` 进 `.gitignore`；任何输出中不泄露真实密钥。
3. **错误规范化** —— 类型化错误类 + 全局处理器；客户端只看到 `{ code, message, requestId }` 结构，**绝不返回堆栈或内部细节**。
4. **边界校验** —— 所有输入在入口处校验，绝不信任客户端数据。
5. **令牌安全** —— 令牌**禁止存 localStorage、禁止放 URL 查询参数**；访问令牌短时效 + 刷新令牌服务端存储。
6. **日志脱敏** —— 结构化 JSON 日志携带请求 ID，不记录密码、令牌与隐私数据。
7. **CORS 显式来源** —— 生产禁用通配符 `*`。
8. **长任务外置** —— 不在请求处理器中执行长任务；后台任务必须幂等 + 重试 + 死信。
9. **数据库变更走迁移** —— 可回滚；多步写入用事务；缓存必带 TTL。
10. **依赖先查后装** —— 引入第三方依赖前先读项目已有清单（package.json / requirements.txt / go.mod），缺失则先给出安装命令并说明用途。

## 前端边界约定

- API 错误映射为可读文案；**4xx 不重试，5xx 自动重试（最多 3 次）**
- fetch 失败显示离线提示，而非静默失败
- 401 触发刷新令牌 → 成功后重放原请求 → 失败则登出

## 测试策略

- 单测：mock 仓储层，保持快
- 集成测试：**用真实数据库**（容器或事务回滚），**不要为速度 mock 服务层**
- 不要为了覆盖率写不验证行为的断言
