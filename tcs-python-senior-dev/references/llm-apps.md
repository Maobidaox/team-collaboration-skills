# LLM 应用开发速查（API 调用 + RAG + Agent）

> 用途：大模型应用开发的工程规范：API 调用、提示词、RAG 落地、评估与安全。这是当前 AI 应用最高频的方向。

## 一、LLM API 调用规范
- 客户端：OpenAI SDK 或兼容协议 SDK（OpenAI Base URL 指向各家）；超时与重试必须配置（指数退避）
- 流式输出：`stream=True` 逐块返回，首 token 延迟是重要体验指标；SSE 或 WebSocket 透传给前端
- Token 管理：请求前估算（`tiktoken`），预留输出空间；超长截断/摘要策略明确
- 结构化输出：优先 JSON Mode / function calling / 响应格式约束（`response_format={"type":"json_object"}`），配合 Pydantic 校验
- 成本控制：缓存（相同请求命中）、模型分级（简单任务用小模型）、批处理

## 二、提示词工程要点
- 结构：系统提示（角色+规则）→ 上下文 → 用户指令 → 输出格式要求
- 关键技巧：few-shot 示例 > 抽象描述；约束"不知道就说不知道"；给输出模板
- 温度：事实/抽取任务用低温度（0–0.3），创意任务 0.7–1.0
- 防 prompt 注入：用户输入与指令隔离（分隔符包裹）、不拼接执行类指令、输出前校验（LLM-as-judge 或规则校验）

## 三、RAG 标准流程
```
文档加载 → 切分 → 向量化 → 存储 → 检索 → 组装 → 生成
```
1. **文档加载**：PDF/HTML/Office 用对应解析器，保留来源元数据
2. **切分（chunk）**：按语义段落/标题切（RecursiveCharacterTextSplitter），chunk 256–1024 token、重叠 10–20%；**切分质量直接决定检索质量**
3. **向量化**：embedding 模型（bge-m3 / text-embedding-3 等），中文用中文优化的模型
4. **存储检索**：中小规模 FAISS/Chroma，生产级 pgvector/Milvus；混合检索（向量 + BM25 关键词）通常更稳
5. **组装**：检索 Top-K（5–10 个）拼入 prompt，注明来源；回答要求"仅基于提供资料"
6. **生成**：LLM 生成 + 引用标注；对关键数字要求回源

## 四、RAG 质量优化顺序
- 先查**检索**（召回不准，生成一定不准）：调切分 → 调 Top-K → 加混合检索 → 重排序（rerank）
- 再查**生成**：增强 prompt（角色/格式/引用要求）→ few-shot → 换模型
- 评估指标：检索 `recall@k` / `mrr`；生成用 LLM-as-judge 按相关性/忠实度/完整性打分，人工抽检兜底

## 五、Agent 开发要点
- 框架：LangChain / LlamaIndex / 各家 Agent SDK；核心是"工具调用 + 循环决策"
- 工具设计：每个工具 = 名称 + 描述（决定模型何时调用）+ 参数 schema（Pydantic）+ 实现
- 循环控制：限制最大步数（防死循环）、工具异常捕获并反馈给模型、关键动作前确认
- 安全：工具白名单、权限最小化、敏感操作（删除/发送/支付）二次确认

## 六、生产注意
- 敏感数据不出域：用户内容脱敏后再送 LLM；本地化部署时选私有化模型
- 合规：不生成违法/有害内容，加内容安全过滤层（关键词 + 模型审核）
- 可观测：记录 prompt/response（脱敏）、token 用量、延迟、失败率，建立成本与质量看板
- 兜底：LLM 输出失败/超时时的降级策略（缓存命中、规则回答、明确报错）
