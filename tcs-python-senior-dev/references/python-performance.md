# Python 性能优化手册

> 用途：性能问题定位与优化流程。核心原则：先测量、后优化；一次只改一个变量。

## 一、性能问题定位流程
1. 先量化：确认瓶颈指标（延迟 / 吞吐 / 内存 / CPU），建立基线
2. 分层定位：入口层（网络/网关）→ 应用层（代码）→ 数据层（DB/缓存）
3. 用 Profiler 找热点，不要凭感觉猜
4. 单变量优化：一次只改一处，改完重新测量对比
5. 防止过早优化：只在有数据支撑时动手

## 二、Profiling 工具
| 工具 | 用途 | 用法 |
| --- | --- | --- |
| cProfile | 函数级耗时统计 | `python -m cProfile -s cumtime app.py` |
| py-spy | 生产环境运行中进程采样 | `py-spy dump --pid <pid>`（不打断服务） |
| line_profiler | 逐行耗时 | `@profile` 装饰器 + kernprof |
| memory_profiler | 内存占用 | `mprof run` 曲线图 |
| 慢查询日志 | 数据库瓶颈 | 定位 TOP SQL 后 EXPLAIN |

## 三、常见瓶颈与解法
| 瓶颈模式 | 表现 | 解法 |
| --- | --- | --- |
| N+1 查询 | 接口慢随列表长度线性恶化 | JOIN / 预加载 / 批量 IN |
| 循环内 IO | 每轮一次 DB/HTTP | 批量处理、异步并发、提出循环外 |
| 深拷贝/大对象 | 内存高、GC 频繁 | 用浅拷贝/生成器/延迟加载 |
| 字符串拼接 | CPU 高 | `join` / f-string |
| 全表扫描 | 慢查询 | 索引 + 查询改写 |
| 缓存未命中 | 重复计算 | Redis 缓存 + 预热 |

## 四、缓存策略（Redis）
- 缓存穿透：查询不存在的数据 → 布隆过滤器 / 空值短缓存
- 缓存击穿：热点 key 过期瞬间并发打库 → 互斥重建（分布式锁）/ 逻辑过期
- 缓存雪崩：大批 key 同时过期 → 过期时间加随机抖动 / 多级缓存
- 一致性：更新先写库后删缓存，或延迟双删；接受短暂不一致
- 内存级：`functools.lru_cache` 用于纯函数结果复用

## 五、异步与并发选型
- IO 密集（网络/DB）：`asyncio` + aiohttp/asyncpg，或线程池
- CPU 密集（计算/加密）：多进程 `ProcessPoolExecutor`（绕开 GIL），或直接上 C 扩展
- 注意：async 中调用同步阻塞 IO 会卡住整个事件循环——这是最常见的"异步没提速"根因
- 连接池：DB/Redis 都复用连接池，禁止每次请求新建连接

## 六、内存优化
- 大数据流式处理：用生成器 / `iter` 分块，不一次性载入
- 类实例瘦身：`__slots__` 用于大量实例场景
- 内存泄漏定位：`tracemalloc` / `objgraph` 查未释放引用
- 定期观察 RSS 与 GC 统计，设置内存告警
