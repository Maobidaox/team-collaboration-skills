# 数据库设计与 SQL 优化

> 用途：PostgreSQL / MySQL 下的表结构设计、索引与慢查询优化规范。

## 一、表结构设计
- 字段类型匹配语义：整数用 INT/BIGINT，金额用 DECIMAL，时间用 TIMESTAMPTZ，长文本用 TEXT，不用 VARCHAR 存 JSON
- 主键：优先自增/序列；分布式或需合并场景用 UUID（注意索引变大）
- 禁止预留字段（col1/col2）、禁止用字符串拼接列表
- 规范化到 3NF；确需冗余（如计数）时用事务/应用层保证一致性
- 每张表必备：主键、created_at、updated_at；软删除场景加 deleted_at 与唯一索引配合

## 二、索引设计
- 高频过滤/排序字段建索引；WHERE、ORDER BY、JOIN 的列优先
- 联合索引遵循最左前缀：`(a, b, c)` 可命中 `a`、`a,b`、`a,b,c`
- 覆盖索引：查询列都在索引内，避免回表
- 索引失效场景：函数包裹列（`WHERE DATE(ts)=...`）、隐式类型转换、`LIKE '%xx'`、对列做运算
- 控制索引数量：写多读少的表慎加索引；每个索引都是写放大
- 用 `EXPLAIN` 验证：type 从好到差 `const > eq_ref > ref > range > index > ALL`，目标避免 ALL

## 三、慢查询优化流程
1. 打开慢查询日志，定位 TOP SQL
2. `EXPLAIN ANALYZE` 看执行计划与真实耗时
3. 检查：缺索引 / 类型转换 / 全表扫描 / 深分页
4. 优化手段：加索引 → 改写 SQL → 冗余字段 → 缓存（按此顺序）
5. 上线后对比前后耗时与命中率

## 四、事务与锁
- 短事务原则：事务内不做外部 IO/HTTP，锁持有时间尽量短
- 隔离级别：默认即可（MySQL RR / PG RC），按需调整，勿全局升级
- 更新同一行：先查询再更新有竞态，用原子 `UPDATE ... SET x = x + 1` 或 `SELECT ... FOR UPDATE`
- 死锁处理：统一加锁顺序、设置锁等待超时、捕获死锁重试

## 五、分页与批量
- 深分页问题：`OFFSET 100000` 性能差
  - 方案 A：游标分页（`WHERE id > last_id ORDER BY id LIMIT 20`）
  - 方案 B：延迟关联（先取主键再回表）
- 批量写入：`bulk_create` / `executemany` / `COPY`，避免循环单条 INSERT
- 大事务分批提交，避免锁表时间过长

## 六、常见反模式
| 反模式 | 问题 | 改进 |
| --- | --- | --- |
| `SELECT *` | 多余列传输、无法覆盖索引 | 只取所需列 |
| 循环内查询（N+1） | 应用层查询风暴 | JOIN / IN 批量 / 预加载 |
| 无 WHERE 全表更新 | 误操作+锁全表 | 先 SELECT 确认范围再 UPDATE |
| 隐式转换 | 索引失效 | 类型严格一致 |
| 每次请求都 COUNT(*) | 大表扫描 | 缓存计数 / 估算统计 |
