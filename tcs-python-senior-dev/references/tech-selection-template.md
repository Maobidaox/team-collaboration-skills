# 技术选型对比模板

> 用途：资深 Python 全栈开发专家的知识库资产。做技术选型时强制按此结构输出，杜绝"推荐 A 但说不出为什么"。

## 1. 需求与约束确认（先澄清，缺项标注"待确认"）
- 业务目标与规模：预估 QPS / 数据量 / 并发 / 增长预期
- 团队情况：人数、技能栈、可投入学习时间
- 部署环境：云 / 私有化 / 边缘，运维能力
- 预算与时间：许可费用、硬件成本、上线时间线
- 非功能要求：可用性 SLA、合规要求、安全等级

## 2. 候选方案清单
- 列出 2–4 个真正可行的候选
- 说明被排除的方案及排除理由（简短）

## 3. 对比维度（每项 1–5 分并给出依据）
| 维度 | 说明 | 候选A | 候选B | 候选C |
| --- | --- | --- | --- | --- |
| 功能覆盖 | 核心需求满足度，列出不满足项 | | | |
| 性能与扩展性 | 吞吐、延迟、水平扩展能力 | | | |
| 生态与社区 | 文档、组件、活跃度、招聘难度 | | | |
| 上手成本 | 团队学习曲线 | | | |
| 运维复杂度 | 部署、监控、升级、排障 | | | |
| 许可与成本 | 开源协议/商业授权、总拥有成本 | | | |
| 长期风险 | 维护状态、厂商背书、路线图 | | | |
| 安全与合规 | 已知漏洞记录、合规认证 | | | |

## 4. 加权评分（如业务有侧重，按权重加权）
- 给出加权总分与计算方式

## 5. 推荐结论
- 首选方案：一句话结论
- 核心理由：不超过 3 条
- 主要风险与缓解：列出风险 + 应对
- 什么场景下应选备选：明确切换条件

## 6. 落地路线
- 试点 → 灰度 → 全量 → 回滚方案
- 迁移步骤与兼容策略（数据迁移、双写、开关）
