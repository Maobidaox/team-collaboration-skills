# Python 全栈代码审查清单

> 用途：资深 Python 全栈开发专家的知识库资产。审查代码时严格按此清单逐项核对，并按级别输出结论。

## 问题分级
- P0 阻断：必须修复才能上线（安全漏洞、数据丢失、明确逻辑错误）
- P1 严重：强烈建议修复（性能瓶颈、异常处理缺失、架构隐患）
- P2 建议：改进项（可维护性、代码质量）
- P3 提示：风格与小优化

## A. 正确性与逻辑
- [ ] 边界条件：空输入 / None / 0 / 超大值 / 超长文本 / Unicode
- [ ] 并发与竞态：共享状态是否加锁、事务隔离级别、操作是否幂等
- [ ] 异常处理：是否吞异常（except: pass）、是否裸捕获、finally 是否正确释放资源
- [ ] 数据一致性：事务边界是否完整、部分失败是否回滚
- [ ] 时间与时区：是否统一 UTC 存储、边界转换是否正确

## B. 安全（P0 优先）
- [ ] SQL 注入：仅用参数化查询 / ORM，禁止字符串拼接 SQL
- [ ] 认证授权：密码哈希（bcrypt/argon2）、JWT 过期与签名校验、水平越权（IDOR）检查
- [ ] Web 安全：XSS 转义、CSRF 防护、CORS 白名单、SSRF 防护
- [ ] 敏感信息：密钥不硬编码、.env 不入版本库、日志不打印密码/token/手机号
- [ ] 依赖安全：已知 CVE 版本、已停止维护的库、废弃 API
- [ ] 输入校验：文件上传类型与大小、请求体大小限制、路径穿越防护

## C. 性能
- [ ] 是否存在 N+1 查询（ORM 是否预加载/联表）
- [ ] 索引是否缺失、是否全表扫描（EXPLAIN 验证）
- [ ] 循环内是否调用 IO / DB / HTTP（应提出循环外或批量处理）
- [ ] 大结果集是否一次加载（应分页/流式/游标）
- [ ] 缓存策略：命中率、缓存穿透/击穿/雪崩防护
- [ ] 异步阻塞：async 函数中是否调用同步阻塞 IO（卡事件循环）
- [ ] 前端：大列表渲染、重复请求、图片懒加载

## D. 可维护性
- [ ] PEP 8、命名规范、类型标注（mypy 可过）
- [ ] 函数/类职责单一，过长函数是否拆解
- [ ] 重复代码（DRY）、魔法数字是否常量化
- [ ] 注释写"为什么"而非"是什么"
- [ ] 依赖管理：requirements/pyproject 锁定版本、最小依赖原则

## E. 架构
- [ ] 分层清晰（路由 → 服务 → 数据访问），依赖方向正确
- [ ] 是否存在循环依赖、模块边界是否清晰
- [ ] 配置管理：环境区分（dev/test/prod）、配置是否集中
- [ ] 接口设计：REST 规范、统一错误码、版本兼容策略

## F. 测试与可观测性
- [ ] 核心逻辑是否有单测（覆盖边界 + 异常路径）
- [ ] 测试是否独立可重复（不依赖执行顺序、外网、共享数据库）
- [ ] 日志：关键操作留痕、结构化、不泄露敏感信息
- [ ] 监控：关键指标与告警是否具备

## 审查输出模板
### [P0/P1/P2/P3] 问题一句话标题
- 位置：文件路径:行号
- 问题：一句话描述
- 影响：为什么需要修复
- 修复建议：给出可直接替换的代码示例
