# 看板布局与信息架构（Step 5）

## 一、核心原则：一眼可决策、操作最短

- **总览页只放「今天必须知道 + 必须做」**，不是把所有数据堆上去
- **明细下钻到二级**：总览 → 分类 → 详情 → 操作，不要一屏塞完
- **操作路径 ≤ 3 次点击**：从发现问题到处理完成，超过 3 步就要重设计
- **每个指标都要能追问「所以呢」**：不能只看数字，要有对应的下一步动作入口

## 二、总览页区块模板

```
┌─────────────────────────────────────────────────────┐
│ 指标卡区（4 个以内，只放关键结果）                      │
│ ┌────────┬────────┬────────┬────────┐               │
│ │今日待办│ 逾期数 │本周完成│ 转化率 │               │
│ │   12   │  3 ⚠  │   28   │ 24.5% │               │
│ └────────┴────────┴────────┴────────┘               │
├─────────────────────────────────────────────────────┤
│ 需要我处理（按紧急排序，带一键操作按钮）                │
│  ⚠ 客户 A 已逾期 2 天      [处理] [延期]             │
│  ⚠ 工单 #1023 未响应        [响应] [转派]             │
│  · 客户 C 今日跟进          [完成]                    │
├─────────────────────────────────────────────────────┤
│ 近期趋势（近 7 天折线，用于判断方向而非精确读数）        │
└─────────────────────────────────────────────────────┘
```

**指标卡设计四要素**：数值（大字） + 标签（是什么） + 对比（环比/同比，带涨跌色） + 阈值态（正常/警告/危险）。

```markdown
| 指标 | 定义口径 | 更新频率 | 告警阈值 | 点击后去哪 |
|------|---------|---------|---------|-----------|
| 逾期数 | 状态≠完成 且 截止<现在 的任务数 | 每小时 | >5 标红 | 逾期任务列表 |
```

**指标必须写清口径**——「完成率」不说明分子分母，两个人能算出两个值。

## 三、三种视图的选择

| 视图 | 适用 | 不适用 |
|------|------|--------|
| **列表** | 字段多、需筛选排序、要批量操作 | 想看阶段流转 |
| **看板（Kanban）** | 有明确状态流转、阶段数 ≤6 | 状态多于 6 个或并行状态 |
| **日历** | 强时间属性（排期、预约、截止） | 没有时间维度 |
| **图表** | 看趋势与分布 | 需要精确值或要操作 |

**默认给列表 + 一种增强视图**（看板或日历），不要同时上四种。

## 四、信息架构写法

```
工作台
├─ 首页/总览（关键指标 + 今日待办）      ← 所有人默认落地页
├─ 任务中心（列表/看板/日历 三视图）
│   ├─ 我的任务
│   └─ 团队任务（组长可见）
├─ 数据看板（按主题分页：业绩 / 效率 / 质量）
├─ 通知中心（异常、待办、审批集中）
├─ 知识库（SOP、FAQ）
└─ 设置（权限、集成、自动化规则）
```

主导航形式：

- **模块 ≤5 个** → 顶部标签（横向，一眼看全）
- **模块 >5 个** → 左侧边栏（可折叠，配图标 + 文字）
- **角色差异大** → 同一入口，按角色渲染不同导航项（**不要搭两个工作台**）

## 五、空状态与加载态（工作台最容易漏）

| 状态 | 要求 |
|------|------|
| **空** | 说明「为什么空」+ 下一步动作按钮；新用户首次进入要有引导（不是空白页） |
| **加载** | 骨架屏而非转圈；指标卡先出数字、图表后加载 |
| **异常** | 数据源不可用时显示「数据更新于 X 时间，当前同步失败」而不是假数据或空白 |
| **无权限** | 明确说明「需要 X 权限，联系 Y 申请」，不要直接隐藏导致用户以为功能不存在 |

## 六、看板设计反模式

| 反模式 | 问题 | 改法 |
|--------|------|------|
| 一屏 20 个指标卡 | 什么都是重点 = 没有重点 | 总览 ≤4 个，其余下钻 |
| 只有图表没有操作入口 | 看到了问题却要跳别处处理 | 异常项旁边直接放操作按钮 |
| 指标无口径说明 | 各人理解不同 | 每个指标配口径表 |
| 所有角色同一屏 | 销售要看客户，组长要看团队，互相干扰 | 按角色分视图 |
| 实时刷新的大屏 | 没人盯着看，还费资源 | 按需刷新 + 异常才告警 |
| 深色底 + 霓虹色炫技 | 长时间看疲劳，打印/截图不可用 | 克制配色，优先可读性 |

## 七、移动端取舍

工作台常有「路上看一眼」的需求，移动端只保留三件事：今日待办、关键指标、待我处理。**不做复杂筛选与批量操作**（屏幕不够，误操作率高），需要时引导到桌面端。
