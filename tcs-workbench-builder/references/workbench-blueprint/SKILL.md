# 工作台蓝图（Workbench Blueprint）技能

本技能为「搭台师」专家提供一套可复用的工作台搭建方法论与交付模板。目标：把含糊的「帮我搭个工作台」转化为一份**结构化、可落地、可评审**的蓝图文档。

## 何时使用
- 用户请求设计/搭建工作台、操作中枢、个人/团队工作空间。
- 用户描述了一批零散工具、重复流程、看不到的数据，希望整合。
- 用户需要模块清单、信息架构、集成方案或自动化编排。

## 核心方法论（6 步）
1. **需求澄清**：明确使用者、痛点、成功标准（用 3 个问题快速对齐）。
2. **角色与场景地图**：列出使用者角色及其典型任务流。
3. **模块架构设计**：模块清单 + 优先级 + 信息架构。
4. **集成与数据流**：接入点、数据源、API、自动化桥接。
5. **交互与可视化**：页面区块布局 + 关键看板草图。
6. **落地路线**：MVP → 迭代，里程碑 + 验收口径。

## 执行铁律
- 永远先交付 **MVP（2 周内可跑通）**，再给长期演进版。
- 模块用表格呈现：`模块名 / 解决什么 / 优先级 / 依赖 / 集成方式`。
- 自动化规则用四要素：`触发 → 条件 → 动作 → 通知`。
- 选型给「推荐 + 备选 + 理由 + 成本/锁定风险」。
- 优先**自包含、低代码、可迁移**方案，不强行绑定单一外部平台。
- 未知的系统/权限标注「待确认」，不臆造。

## 交付物
主交付物为《工作台蓝图》，直接套用 `templates/workbench-blueprint.md`。
模块灵感与常见集成方式参考 `references/module-library.md`。

## 输出格式约定
- 用 Markdown 交付，含以下章节：目标与角色、模块清单（带优先级表格）、信息架构、集成与数据流、自动化规则、看板布局、落地里程碑（MVP/长期）。
- 明确区分「方案蓝图」与「真正搭建」：本技能默认产出设计文档；若用户要求实际建文件/写配置/接 API，先确认环境与权限。
