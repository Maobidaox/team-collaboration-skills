# 自动化规则设计（Step 4 细化）

## 一、四要素写法（缺一不可）

```
触发 → 条件 → 动作 → 通知
```

| 要素 | 要写清什么 | 反例 |
|------|-----------|------|
| **触发** | 时间（cron 表达式或明确时刻）/ 事件（什么动作发生） | 「定期」（多久？） |
| **条件** | 可判定的布尔判断，含阈值具体数值 | 「数据异常」（什么算异常？） |
| **动作** | 具体做什么，操作哪个系统的哪个对象 | 「处理一下」 |
| **通知** | 通知谁、走什么渠道、含什么内容 | 「通知相关人员」（谁？怎么通知？） |

**判定标准**：把这条规则交给一个不了解背景的人，他能否无歧义地执行？不能就重写。

## 二、四类触发类型

| 类型 | 适用 | 例 |
|------|------|----|
| **时间触发** | 周期性汇总与推送 | 每日 9:00 生成日报、每周一 8:30 出周报 |
| **事件触发** | 有新数据/状态变更 | 新表单提交 → 建任务并指派 |
| **条件触发** | 指标越阈、逾期、异常 | 工单 2 小时未响应 → 升级给主管 |
| **审批流** | 需要人工决策的链路 | 提交 → 审批 → 执行（请假、采购、发布） |

## 三、可抄的 8 条规则范例

| # | 规则 | 触发 | 条件 | 动作 | 通知 |
|---|------|------|------|------|------|
| R1 | 日报自动生成 | 每日 9:00 | 无 | 汇总昨日新增/完成/逾期数，生成摘要 | 推送到企微群 + 组长 |
| R2 | 逾期提醒 | 每小时整点 | 任务状态≠完成 且 截止时间 < 现在 | 标记逾期并生成待办 | @负责人（同一任务 24h 内只推 1 次） |
| R3 | 紧急工单升级 | 工单创建时 | 优先级 = 紧急 | 建任务并指派给值班人 | @值班人 + 主管 |
| R4 | SLA 预警 | 每 15 分钟 | 首次响应为空 且 已过 SLA 的 80% | 标记「即将超时」 | @负责人 |
| R5 | 新线索分配 | 新线索入库 | 归属为空 | 按轮转规则分配给销售 | @被分配人 + 记录分配日志 |
| R6 | 指标越阈告警 | 每小时 | 当日转化率 < 上周同日 × 0.7 | 生成异常卡片并附对比图 | 推到运营群 |
| R7 | 周报自动汇总 | 每周一 8:30 | 无 | 汇总上周完成/延期/风险项 | 邮件发给管理层 |
| R8 | 数据同步失败兜底 | 同步任务失败 | 重试 3 次仍失败 | 标记数据源异常、暂停下游自动化 | 告警给管理员（**必须告警**） |

## 四、兜底与防失控（最容易漏）

每条自动化都要回答这四个问题，答案写进规则表备注列：

1. **失败怎么办** —— 重试几次？间隔多久？（建议 3 次、指数退避）仍然失败 → 告警 + 转人工
2. **会不会重复执行** —— 幂等键是什么？（用业务唯一 ID，不要用时间戳）
3. **会不会刷屏** —— 同一对象多久内只推一次？（如同一任务 24h 内只提醒一次）
4. **会不会误伤** —— 条件边界是否可能误判？（如「逾期」是否排除已申请延期的）

```markdown
| 规则 | 触发 | 条件 | 动作 | 通知 | 兜底 |
|------|------|------|------|------|------|
| R2 逾期提醒 | 每小时整点 | 状态≠完成 且 截止<现在 且 未延期申请 | 标记逾期 | @负责人 | 同一任务 24h 内去重；推送失败重试 3 次后告警管理员 |
```

## 五、哪些不该自动化

| 不该自动化 | 原因 |
|-----------|------|
| 需要主观判断的决策 | 规则写不出来，硬写会误判 |
| 低频（月均 <2 次）的操作 | 自动化收益 < 维护成本 |
| 失败代价不可逆的动作 | 如删除、对外发送、扣款——必须人工确认 |
| 源数据质量不可靠的流程 | 垃圾进垃圾出，先治理数据 |
| 还没稳定下来的流程 | 流程每周都在变，自动化会持续返工 |

**判断口诀**：高频 + 规则明确 + 失败可逆 = 适合自动化。三缺一不做。

## 六、MVP 阶段的自动化取舍

MVP 只上 **1–2 条**，且必须满足：触发明确、动作简单、失败可人工补齐。

- ✅ 好选择：日报自动汇总（失败了人工补一份也不难）
- ❌ 坏选择：自动派单 + 自动升级 + 自动关闭（任一环出错都会连锁放大）

先跑通一条，观察两周再加密。
