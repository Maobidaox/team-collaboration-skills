# 落地路线与验收（Step 6）

## 一、MVP 边界：2 周内可跑通

**MVP 判定标准**：使用者能**独立完成一条完整的主任务流**，从进入到拿到结果，不需要人工在台前幕后补位。

| 应在 MVP 内 | 应在 MVP 外 |
|------------|------------|
| 1 个角色（最核心的那个） | 多角色与权限分级 |
| 2–3 个 P0 模块 | P1/P2 模块 |
| 1 条自动化（简单、失败可人工补） | 自动化链路串联 |
| 1–2 个数据源 | 全量数据源接入 |
| 手工兜底可用 | 完善的异常处理与监控 |

**P0 模块超过 5 个就是一个信号**：说明还没砍到位，2 周跑不通。砍的办法是问「去掉它，主任务流是否走不下去？」，答「还能走」就降级到 P1。

## 二、两周排期模板

```markdown
| 阶段 | 时间 | 事项 | 产出 | 负责人 | 验收 |
|------|------|------|------|--------|------|
| 调研 | D1–D2 | 需求澄清、现状盘点、确认数据源权限 | 调研笔记 + 待确认清单 | 搭台师 | 成功标准已明确且可验证 |
| 设计 | D3–D4 | 模块清单、信息架构、看板草图 | 《工作台蓝图》精简版 | 搭台师 | 用户确认 P0 范围 |
| 搭建 | D5–D9 | 建模块、配字段、接入 1 个数据源 | 可访问的工作台 | 搭台师 + 业务负责人 | 数据能正常同步，字段映射正确 |
| 自动化 | D10–D11 | 上 1 条核心自动化 + 兜底 | 规则配置 + 测试记录 | 搭台师 | 手动触发与定时触发均产生预期结果 |
| 试用 | D12–D14 | 真实使用者跑主任务流，收集问题 | 问题清单 + 修复记录 | 业务负责人 | 使用者无协助下独立完成主任务流 |
```

## 三、验收口径（必须可判定）

**坏验收**：「系统好用」「效率提升了」「大家满意」——无法判定，等于没验收。

**好验收**：

| 维度 | 验收口径 | 判定方式 |
|------|---------|---------|
| 功能 | 使用者能独立完成「查看今日跟进 → 更新状态 → 生成日报」 | 现场走一遍，无协助 |
| 数据 | 数据源同步成功率 ≥99%，失败有告警 | 查看一周同步日志 |
| 自动化 | 日报每日 9:00 自动生成，一周内无漏发 | 检查推送记录 |
| 时效 | 逾期任务 30 分钟内推送到负责人 | 造一条逾期任务计时 |
| 体验 | 主任务流 ≤3 次点击完成 | 数点击次数 |
| 稳定 | 连续 5 个工作日无需人工在后台补数据 | 询问使用者 |

每条验收写清**怎么判定**（现场走一遍 / 查日志 / 造数据计时），否则验收时必然扯皮。

## 四、长期演进路线（MVP 之后）

```markdown
### 长期演进（MVP 后按季度推进）
- **Q1**：接入剩余数据源 → 权限分级 → 上线 P1 模块
- **Q2**：自动化加密（升级、SLA 预警）→ 多维分析看板
- **Q3**：跨团队复用 → 模板化沉淀 → 高级预警

> 每个季度开始前重评审一次：MVP 的实际使用数据会改变优先级，不要照抄初版路线。
```

**关键**：长期路线只给方向和排期粗框，不给死承诺——MVP 跑起来后，真实使用数据会推翻一半当初的设想。

## 五、常见失败模式

| 失败模式 | 症状 | 预防 |
|---------|------|------|
| **大爆炸式交付** | 一次上 10 个模块，3 个月没上线 | 强制 MVP 2 周 + P0 ≤5 |
| **没人用** | 搭好了，两周后无人打开 | MVP 阶段就拉真实使用者试用，不是搭完再推广 |
| **数据不准** | 看板数字和业务系统对不上 | 上线前人工核对一次口径与数值，留核对记录 |
| **自动化失控** | 半夜疯狂推送、重复建单 | 去重 + 幂等 + 失败告警（见 automation-recipes.md） |
| **强绑平台** | 平台涨价/下线，工作台跟着完蛋 | 选可导出的标准格式，定期检查导出可用性 |
| **权限失控** | 谁都能看全部客户数据 | 敏感字段按角色授权 + 操作审计 |
| **方案≠落地** | 蓝图写得很漂亮，执行时发现接口不存在 | **先验证关键权限与接口存在，再写完整方案** |

## 六、交付后必须留的三样东西

1. **待确认清单** —— 未知项集中列出，写明「谁去确认、何时有结果」
2. **已知限制** —— 当前方案不覆盖什么、什么情况下会不准，明确告知（藏着不说，用户踩坑时信任崩塌）
3. **下一步建议** —— 2–3 条具体可执行动作，附优先级与预估成本
