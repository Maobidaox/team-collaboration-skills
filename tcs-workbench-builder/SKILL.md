# 工作台搭建工作流

把含糊的「帮我搭个工作台」转化为**结构化、可落地、可评审**的《工作台蓝图》，再按 MVP → 迭代推进。

## 何时使用

- 用户请求设计/搭建工作台、操作中枢、个人或团队工作空间
- 用户描述了一批零散工具、重复流程、看不到的数据，希望整合
- 用户需要模块清单、信息架构、集成方案或自动化编排
- 需要一屏可决策的看板，或想把日报/周报/提醒自动化

**不适用**：单个工具怎么用、纯视觉美化、不涉及多系统整合的简单需求。

## 六步工作流

### Step 1：需求澄清（先问后做，不要凭空设计）

开局三问对齐：

1. **这个工作台主要给谁用？**（个人 / 某个团队 / 整个部门）
2. **最想解决的 1–3 个痛点是什么？**（任务散落 / 重复手工 / 数据看不到 / 协同断点）
3. **要「方案蓝图」还是「直接搭一个能跑的最小工作台」？**

再补全成功标准：「怎样算搭好了」必须是可验证的（任务集中在一处、日报自动出、异常 10 分钟内有提醒），而不是「好用」。完整提问清单见 `references/discovery-questions.md`。

### Step 2：角色与场景地图

列出使用者角色及其**典型一天/典型任务流**（早晨看什么 → 处理什么 → 交给谁），以及每个角色最关心的那一个数。角色超过 3 个时，说明这不是一个工作台能解决的，要拆分或做角色视图。

### Step 3：模块架构设计

输出模块清单，用表头固定的表格：`模块名 / 解决什么 / 优先级 / 依赖 / 集成方式`。优先级 **P0 = MVP 必须有，P1 = 二期，P2 = 长期增强**。

模块灵感从 `references/workbench-blueprint/references/module-library.md` 挑选组合（通用基础 5 个 + 销售/培训/项目管理/内容/客服五类场景模块），按业务裁剪，不要照抄全集。

### Step 4：集成与数据流方案

明确接入系统、数据流方向（源 → 工作台 → 目标）、同步频率（实时/每小时/每日）、集成方式。**集成方式按梯度选，自包含优先**：

原生/低代码 → 连接器/Webhook → API 桥接 → 导出导入（兜底）

凭证、权限、字段可得性未知的，一律标注「**待确认**」，**绝不臆造**系统名、字段名或接口能力。详见 `references/integration-playbook.md`。

### Step 5：交互与可视化原型

给出页面区块布局与关键看板草图（文本/ASCII 即可）。原则是**一眼可决策、操作路径最短**：总览页只放「今天必须知道和必须做的」，明细下钻到二级。布局模式与看板写法见 `references/dashboard-layout.md`。

### Step 6：落地路线图

拆成 **MVP（2 周内可跑通）** + **长期演进**两个版本，列出里程碑、负责人、验收口径。MVP 必须能独立完成一条主任务流，而不是「各模块都能点开」。排期与验收见 `references/rollout-checklist.md`。

## 执行铁律

1. **先 MVP 后扩展** —— 永远先交付一个能跑起来的小工作台，再逐步加模块；一次性大爆炸必失败。
2. **模块用表格** —— `模块名 / 解决什么 / 优先级 / 依赖 / 集成方式`，五列齐全。
3. **自动化四要素** —— `触发 → 条件 → 动作 → 通知`，缺一不可。
4. **选型三件套** —— `推荐方案 + 备选 + 理由`，并标注成本与锁定风险。
5. **自包含优先** —— 低代码、可迁移；不强行绑定单一外部商业平台，除非用户明确接受。
6. **未知即待确认** —— 不臆造系统、字段、权限、数据量。
7. **区分建议与落地** —— 默认产出设计文档；真要建文件/写配置/接 API，**先确认环境与权限再动手**。

## 边界规则

- **敏感数据** —— 涉及客户信息、业绩、薪酬等，方案中必须写明脱敏方式、最小权限与操作审计。
- **不承诺效果** —— 可以说「预计减少 X 类重复操作」，不能承诺「效率提升 50%」这类无法验证的数字。
- **不过度设计** —— P0 超过 5 个模块通常意味着 MVP 跑不通，要砍。

## 交付格式

默认交付《工作台蓝图》（Markdown），章节顺序固定：**目标与角色 → 模块清单（带优先级表格）→ 信息架构 → 集成与数据流 → 自动化规则 → 看板布局 → 落地里程碑（MVP/长期）**，末尾附选型备注（推荐 + 备选 + 理由 + 成本/锁定风险）与待确认清单。

若用户要的是「直接搭起来」，则蓝图先给精简版（目标 + P0 模块 + 一条自动化 + 验收口径），确认后立即进入实施，不要先写 3000 字文档。
