# 七步交付 Playbook

每步的产出模板。工程级任务按序推进，简单问题直接跳到结果。

## Step 1 对齐目标

```
目标：用一两句话复述用户要解决什么问题
成功标准：可验证的判定条件（如「P95 < 200ms」「日订单 10 万不丢单」）
待确认：[量级 / 并发 / 部署环境 / 交付时间 / 已有技术栈] —— 一次性问清，不猜
```

缺失关键信息的后果是返工，宁可先问一轮。问完即进入下一步，不要反复追问。

## Step 2 拆解需求

```
功能清单：
- F1 xxx（输入 / 输出 / 异常路径）
- F2 xxx

非功能约束：性能（QPS、P95）、安全（认证、审计、数据分级）、可用性（SLA、降级策略）
依赖与风险：外部系统、数据迁移、人员/环境依赖
本期不做：显式列出（避免过度设计与范围蔓延）
```

验收标准与功能清单一一对应，每条可判定。

## Step 3 方案设计

```
技术选型：
| 方案 | 优势 | 劣势 | 适用边界 |
| A（推荐） | ... | ... | ... |
| B | ... | ... | ... |
推荐 A 的理由：...

架构分层：[接入层 / 应用层 / 领域层 / 数据层] 与模块边界
数据模型：核心实体、关系、索引方向
接口契约：API 列表（路径、请求、响应、错误码）
容量估算：写清假设（单机规格、单请求成本、峰值倍数）与推算过程
关键取舍点：为什么不用另一个方案
```

选型必须给对比，让用户有能力否决方案。

## Step 4 编码实施

- 先跑通**最小闭环**（一个端到端可运行的路径），再逐层补齐
- 按模块提交，每个模块给出目录结构与关键实现说明
- 代码块标注语言 + 文件路径；省略处用 `// ...` 并说明省略内容
- 不写伪代码充数；关键逻辑给可执行实现
- 关键路径埋日志与排障线索（request ID、耗时、关键状态）

## Step 5 测试验证

```
测试金字塔：
- 单元：核心逻辑、边界条件（空值/极值/异常输入）
- 集成：DB、缓存、MQ、外部依赖（用真实容器或合约测试，不 mock 一切）
- 端到端：关键业务路径 + 并发竞态场景

本地复现命令（可直接复制）：
$ <build>
$ <test>
预期输出：<...>
```

用覆盖率以外的指标判断质量：边界覆盖、竞态覆盖、失败路径可观测性。没跑过的代码标注「未执行验证」。

## Step 6 发布上线

```
部署方式：<容器 / 虚拟机 / Serverless>，制品来源与版本
配置项与环境变量：列表 + 默认值 + 是否敏感（敏感值只给占位符）
数据库变更：迁移脚本、是否可回滚、是否需要双写/灰度读
灰度策略：流量比例、观察窗口、判定指标
回滚方案：触发条件、操作步骤、预计耗时、数据兼容性
上线后监控：核心指标清单（错误率、P95、队列积压、资源水位）+ 告警阈值
```

发布目标是「无聊、可重复」：任何一步都要能写清楚触发条件与操作。

## Step 7 复盘与迭代

```
已知技术债：条目 + 影响面 + 建议处理时机
后续优化方向：可量化的下一步（目标值 / 当前值 / 预期收益）
防复发机制：监控、告警、自动化检查、文档
```
