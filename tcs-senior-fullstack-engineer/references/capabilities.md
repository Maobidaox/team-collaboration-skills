# 九项核心能力实操要点

每项给「做什么 / 产出 / 检查点」。需要深入时结合项目实际技术栈查阅官方文档，不确定的 API 与配置项标注「需要确认」。

## 1 需求分析与拆解

把模糊业务诉求翻译成明确的功能边界、输入输出、异常路径与验收标准；识别隐性需求（幂等、审计、对账、运营后台）与过度设计。

产出：可直接排期的任务清单 + 验收标准 + 本期不做清单。
检查点：每条需求都有异常路径说明；每条验收标准可判定。

## 2 技术选型与架构设计

按业务规模、团队能力、演进节奏做取舍。输出分层架构、模块边界、接口契约、数据模型与容量估算，并写清「为什么不用另一个方案」。

检查点：至少两个候选方案；容量估算写清假设与推算；模块间依赖无环。

## 3 多语言编码实现

| 语言 | 主要场景 | 典型坑 |
|------|---------|--------|
| Java | 企业级服务、Spring 生态 | JVM 调优、线程池与连接池配置、依赖膨胀 |
| JavaScript/TypeScript | Node 服务与前端 | 类型边界不严、异步错误丢失、依赖供应链 |
| Python | 脚本、服务、数据处理 | GIL 与并发模型、依赖环境漂移 |
| Rust | 系统级与高性能组件 | 学习曲线与交付节奏、 unsafe 边界 |
| C++ | 底层与性能敏感模块 | 内存生命周期、构建与 ABI 兼容 |
| C# | .NET 应用 | 跨平台部署与运行时版本 |

按场景选最顺手的语言，而不是最熟悉的。确实需要省略实现时标注 `// ...` 并说明。

## 4 前后端全栈贯通

打通数据库、缓存、消息队列、API 网关到 React/Vue 页面与 BFF 层；定位性能瓶颈时逐层测量（客户端 → 网关 → 服务 → 缓存 → DB），不凭猜测下结论。

检查点：每层有耗时埋点；能回答「到底是谁在拖慢响应」。

## 5 测试与质量保障

设计测试金字塔：单元（核心逻辑与边界）、集成（DB/缓存/MQ/外部依赖，优先真实容器或合约测试）、端到端（关键业务路径与并发竞态）。

检查点：边界条件（空值、极值、异常输入）与并发竞态有对应用例；质量判断不只看覆盖率。

## 6 性能优化与容量规划

压测建模（目标 QPS、峰值倍数、数据规模）→ 测量（火焰图、慢查询日志、指标面板）→ 定位 → 优化 → 复测。手段包括慢查询治理、缓存策略、连接池与线程池调优。

产出：优化前后的**量化对比**与估算依据。
检查点：给出数字与测量方法，不用「更快」「更好」；优化后必须复测确认。

## 7 代码审查与重构

识别坏味道、循环依赖、隐藏耦合、安全隐患（注入、XSS、越权、密钥硬编码）。重构在不破坏现有行为的前提下分步推进：

```
1. 补测试锁定现有行为 → 2. 小步解耦（先加接缝，不改逻辑）→ 3. 逐层替换 → 4. 删除旧路径
```

检查点：每步可独立提交与回滚；有行为对比验证。

## 8 CI/CD 与发布上线

流水线：构建 → 静态检查（lint / 类型 / 安全扫描）→ 自动化测试 → 制品管理 → 灰度 → 回滚预案。目标是让发布变成无聊的、可重复的事。

检查点：流水线可在干净环境一键复现；制品可追溯；回滚步骤经过演练或至少书面验证。

## 9 线上问题排查

顺序：**先止血，再定位根因**。从监控指标、链路追踪、日志与堆栈入手：

```
影响面与止损（降级 / 回滚 / 限流）→ 时间线对齐（变更、发布、流量）→ 定位（指标→链路→日志→堆栈）
→ 根因修复 → 防复发机制（监控、告警、自动化检查、文档）
```

检查点：给出止血方案优先于根因分析；最终必须补上防复发机制。
