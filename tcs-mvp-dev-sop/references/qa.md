# 测试工程师规范（严过关）— 先写测试、反作弊、质量门禁

> P0 缺陷不归零，不上线。没有例外。数据驱动的质量评估，不含主观判断。
> 深度规范：`knowledge/01-standards/test-discipline.md`（测试纪律）、`test-integrity-anti-gaming.md`（反作弊）、`verifier-critic-pattern.md`（验证者模式）、`generated-code-failure-modes.md`（失效模式）、`production-readiness-scorecard.md`（生产就绪记分卡）。

## P0 规则认知（作为测试项）

- 代码中检测到 emoji 作为 UI 功能图标 = **P0 缺陷**，打回前端
- 紫粉渐变 = P1 严重；"Welcome to" / "Lorem ipsum" 空洞占位 = P1 严重

## 先写测试原则（核心）

**写测试的角色 ≠ 写代码的角色。** 同一 agent 写实现又写测试会产生「同义测试反模式」——测试复述实现假设，绿灯零信息量（AgentCoder 实验：分离角色 91.5% vs 混合 86.8% pass@1）。

工作流：Phase 2（设计细化）时基于 Spec 的 EARS 验收标准**先编写测试用例**（覆盖正常路径 + 异常路径 + 边界值 + 权限 + 状态）；Phase 3 开发按已写好的测试实现；Phase 4 跑测试 + 评审 + 出质量报告。

## 测试金字塔

```
         /  E2E  \        少量：核心用户旅程
       /----------\
      /Integration \      中等：API + 数据库
     /--------------\
    /   Unit Tests   \    大量：函数、工具类
```

## 测试完整性反作弊门（P0 级门禁）

AI 生成代码会作弊：删测试换绿、弱化断言、加 skip。对比开发前后测试 surface，发现**任一**即阻断（P0 缺陷）：

| # | 作弊类型 | 检测方法 |
|---|----------|----------|
| 1 | 测试文件/用例被删 | `git diff --name-status` 检测测试文件删除或行数骤减 |
| 2 | 断言数下降 | 对比前后 `expect(`/`assert ` 调用数量 |
| 3 | 新增 skip/xfail/.only | `grep -rn 'skip\|xfail\|\.only\|focus' tests/` 对比新增 |
| 4 | 断言硬编码实现输出 | 人工审查：断言值来自 Spec 定义而非实现返回值 |
| 5 | 测试框架配置篡改 | `git diff jest.config.* pytest.ini package.json` 检查 scripts.test/coverage 阈值变更 |

## 改动影响分析（每次测试前必做）

拿到 diff 先回答「这次改了什么 → 波及哪些旧行为 → 风险面优先级」：改动范围（文件/函数/类型）→ 下游影响面（直接调用方/共享状态）→ 旧行为风险分级（高→必测 / 中→应测 / 低→抽测）。

## Phase 4 测试流程

1. 改动影响分析 → 反作弊门（5 类检测）
2. **冒烟测试**（30 分钟内）——核心流程不通 = 直接打回
3. 功能测试逐条验证：正常路径 / 异常路径（网络错误、输入错误、业务规则冲突）/ 边界值（空值、最大值、格式错误）/ 权限控制（不同角色行为差异）
4. 回归测试——基于改动影响分析，验证受影响旧行为仍正常；**回归率非零不算完成**
5. 失效模式核对（6 类，同前端/后端清单）
6. 生产就绪评级（7 维 × 3 档）→ 输出质量报告

## 缺陷分级

| 级别 | 定义 | 例子 | 上线策略 |
|------|------|------|----------|
| **P0 致命** | 阻塞核心流程 | 无法登录、支付失败、数据丢失、emoji 作 UI 图标 | 必须全部修复才能上线 |
| **P1 严重** | 影响体验不阻塞 | 页面慢、提示不友好、紫粉渐变 | 至少修复 80% |
| **P2 一般** | 视觉瑕疵、偶发 | 对齐偏差、偶发 500 | 记录进 Backlog |

## 安全测试（OWASP Top 10 MVP 必查）

| 风险 | 测试方法 | 预期 |
|------|----------|------|
| XSS | 注入 `<script>alert('xss')</script>` | 被转义不执行 |
| SQL 注入 | 输入 `' OR 1=1 --` | 参数化不泄露 |
| CSRF | 跨域 POST | 无 Token 被拒 |
| 越权 | 普通用户 token 访问管理员 API | 403 |
| 敏感泄露 | 检查响应中的密码/密钥字段 | 不返回/脱敏 |
| 未认证 | 无 token 访问受保护 API | 401 |

另查：服务端校验（不只依赖前端）/ JWT 过期机制正确 / 密码 bcrypt/argon2 哈希 / 文件上传限制 / 速率限制生效。


## 回归集产物（每个 P0 缺陷必须沉淀）

修复后沉淀为项目级持久回归用例 `tests/regression/<缺陷名>.test.ts`（注释记录缺陷描述/发现日期/修复方式），回归集进版本库每次改动都跑，只增不轻易删。
