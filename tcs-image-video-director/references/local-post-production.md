# 本地后期与装配

只在用户要**真装配**（多镜拼成片、加字幕、混音、导出）或要跨会话续作时使用。纯方案讨论不建项目。

## 一、能力预检

| 需要 | 依赖 | 缺了怎么办 |
|---|---|---|
| 裁剪拼接、混音、导出 | FFmpeg / ffprobe | 交时间线 JSON + 待执行清单，明说未装配 |
| 烧字幕 | FFmpeg subtitles 滤镜 + 覆盖目标语言的字体 | 交字幕文件（SRT）+ 字号/安全区说明 |
| 台账脚本 | Python 3.11+ | 用同结构的 Markdown 表代替 |

脚本只操作本地文件，**不联网、不生成图像/视频、不替代生成能力**。

## 二、时间线怎么写

先探测真实媒体时长，时间码来自实际素材或已确认的对齐记录——**不从脚本估算后再声称已完成语音对齐**。

```json
{
  "width": 720, "height": 1280, "fps": 30,
  "font": "Arial",
  "shots": [
    {"file": "clip-a.mp4", "in": 0, "out": 2, "keep_audio": true},
    {"file": "clip-b.mp4", "in": 1, "out": 3, "keep_audio": true}
  ],
  "audio": [{"file": "user-music.wav", "start": 0, "in": 0, "gain": 0.15}],
  "captions": [{"start": 0.2, "end": 1.8, "text": "用户确认过的字幕"}]
}
```

规则：

- 路径相对时间线文件；只接受真实本地素材，远端结果先落到宿主允许的路径
- 默认保留片段原声，无原声补静音轨；明确要替换才设 `keep_audio: false`
- 外挂音轨按 `start` 延迟、`in` 裁前端、`gain` 调音量；**不自动循环音乐、不创建配音**
- 支持硬切、裁剪、按目标画幅等比留边、显式音轨混合、字幕烧入、MP4 导出
- **不支持**自动配音、语音识别、智能踩点、复杂转场、生成式局部编辑——这些记 `unsupported`

## 三、字幕四条

1. 先锁专名、数字、标点与语义分行，再记录时间段、文字、位置与遮挡区
2. 字幕稿 / 可切换字幕 / 烧录字幕 / 动态标题是**四种交付物**，按用户要的给
3. 字体必须实际覆盖目标语言；缺字会显示方框——**成功退出不证明文字正确**
4. 字幕安全区：避开底部按钮区与平台角标位

## 四、导出与抽帧验收

产出三件：`.mp4`、技术证据（`.delivery.json`）、抽帧目录（`.frames/`）。

必看必听：

- 开头、**每个切点**、每个字幕窗口、结尾——抽帧核对
- 完整播放一遍并听：旁白、音乐、原声、断音与爆音

自动探测只能证明流/尺寸/时长等技术项；技术通过必须标记 `rendered_not_creatively_reviewed`，创意验收仍要人看。

## 五、定向修改（版本管理）

- 原版本一律保留，改字幕只更新字幕与时间线 → 输出 `final-v2`
- **不因为改字幕去重跑已经完成的远端生成**
- 只修失败环节；若改动会波及后续依赖状态，明确列出受影响范围，不自动全量重生成

## 六、交付与阻塞

- 交付前确认没有未决任务与待办；有用户待决策项就记 `pending`，拿到明确答复再 `resolve`
- **不要把等待时间当授权**
- 临时链接记有效期，交付前存稳定副本或提醒下载期限

## 七、多语言 / 多画幅

- 中英版本共享事实与服务顺序，但**分别录制与剪出停顿**，不是换字幕
- 横竖版分别校验必要内容不被裁断；同一内容可不同构图，不必重新生成全部素材
- 标志过宽时完整缩放并重排版，**不硬裁文字**
- 只有一版完成时，不能报"多版全部完成"
