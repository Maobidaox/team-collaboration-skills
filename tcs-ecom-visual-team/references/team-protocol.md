# 团队协作协议

本技能是一个 **11 人团队**。成员卡在 `members/`，本文管的是**成员之间怎么协作**，以及**没有组队能力时怎么降级**。

> **内外分工（先记住这一条）**：**麦琪对外**（接单、面对用户、守三道门禁、最终交付与汇报）；**凯对内**（排工、控节奏、推流程、管看板、仲裁升级）。
> 麦琪的产出是「这版能不能交」，凯的产出是「这版还在往前走」。

## 一、两种执行模式（开工前先定）

| 模式 | 适用 | 做法 |
|---|---|---|
| **A 组队模式** | 宿主具备子代理/TeamCreate 能力 | 麦琪建队 → 凯排期 → 按阶段委派 → 成员产出经麦琪中转 → 薇终审 |
| **B 串行模式（默认）** | 单一 agent 环境 | 当前 agent 按十一阶段链路**自行串行执行**，角色名只作阶段标识 |

⚠️ **无论哪种模式，各阶段的产出格式、硬约束、门禁完全一致。** 差异只在谁执行，不在内容标准。串行模式下不要省略任何一道门禁——门禁是内容质量的一部分，不是协作仪式。

> **串行模式下凯依然在场**：只是他不再「派人」，而是管节奏——等用户确认的这段时间先把 5/7 预备做了、卡住时给用户最小可继续步骤、改了三版还没过就停下问。这是串行模式最容易丢掉的能力。

## 二、组队模式的六条铁律

1. **建队只能由主理人执行**，成员严禁自建团队、严禁 spawn 主理人
2. **成员产出不经主理人中转不得流转** —— 成员之间不直连通信，避免上下文丢失与责任不清
3. **主理人不代写专业产出** —— 他只做路由、守门、汇总
4. **委派必须一次写全五要素**（用户原文 / 文件路径 / 已确认事实 / 本次任务 / 验收要求），因为成员不继承本对话全文
5. **门禁不可逆** —— 策略门 → 确认门 → 终审门，未过不得推进
6. **个别槽位失败只补缺口**，绝不整套重跑

## 三、交接契约（跨阶段唯一格式）

上游交给下游，必须带这五件，缺一件下游有权退回：

```
① 产出文件      —— 路径 + 关键内容摘要
② 已冻结内容    —— 用户已确认的文案、Style Lock、证据账本状态
③ 约束清单      —— 下游必须遵守的（逐字冻结项、保真项、禁止项）
④ 待办/缺口     —— 上游没解决、留给下游注意的
⑤ 验收依据      —— 下游按哪个清单判定
```

**已确认文案逐字冻结**是全链路最强约束：下游不得新增、改写、润色，哪怕发现错别字也要退回主理人。

## 四、冲突仲裁（谁说了算）

**由凯按优先级当场裁定，裁定不了的升级麦琪去问用户。** 麦琪不追进度、不裁技术分歧；成员之间不互相说服。

优先级：

```
① 产品真实性  >  ② 合规  >  ③ 转化  >  ④ 审美
```

| 冲突场景 | 判给 |
|---|---|
| 「改了包装更好看」 vs 「包装是真实的」 | 真实性 —— 改回去 |
| 「这句很打动人」 vs 「这句没有证据」 | 合规 —— 删或降级 |
| 「图很美」 vs 「看不出这是什么」 | 转化 —— 先保证识别 |
| 「想加个装饰」 vs 「会遮挡主体」 | 转化 —— 删装饰 |

**审美永远排最后。** 这是电商视觉与艺术设计的根本区别：这里的图是用来卖货的，不是用来参展的。

**升级规则**：涉及商业取舍与用户偏好的分歧（如「要不要为了转化改变品牌调性」），凯一律升级给麦琪，由她问用户，不擅自替用户决定。

## 五、十一阶段 × 十一角色 × 三门禁

**调度贯穿全程**：凯不占阶段位，他决定每个阶段何时启动、哪些可并行、卡住时怎么推。

| # | 阶段 | 角色 | 门禁 | 产出 |
|---|---|---|---|---|
| 0 | 策略与合规 | 凌 | 🔒 **策略门** | `00-visual-strategy.md` |
| 1 | 商品简报 | 小瞳 | | `01-product-brief.md` |
| 2 | 文案 + 套图方案 | 文迪 | 🔒 **确认门** | `02-marketing-copy.md` `03-image-set-plan.md` |
| 3 | **门禁等待（不空转）** | **凯** | | 并行推进 5 / 7 预备 / 10 预备 |

### 并行矩阵（凯的核心工具）

| 可并行 | 说明 |
|---|---|
| 4（提示词）∥ 5（视频脚本） | 同依赖确认门，互不阻塞 |
| 6（生成）∥ 7（精修前几张） | 流水式，先出先修 |
| **确认门等待期** ∥ 5 / 7 预备 / 10 预备 | **门禁等待绝不空转** |
| 10（数据） | 完全独立 |

### 阶段看板（凯维护）

```
| 阶段 | 负责 | 状态 | 产出路径 | 依赖 | 阻塞原因 |
|------|------|------|----------|------|----------|
```

状态四值：**未启 / 进行 / 待确认 / 完成**，外加 **阻塞**（必须带原因）。

## 六、按需成员的触发条件

| 成员 | 何时出场 | 何时跳过 |
|---|---|---|
| **凯** | 同项目 ≥2 位成员在场，**或** 任一阶段发生阻塞 | 单人单阶段的极简任务 |
| 小瞳 | 用户提供了商品参考图 | 用户直接给了完整文字资料（简报可合并进阶段 0） |
| 蒙太 | 用户要视频 | 纯图片任务 |
| 雷 | 环境有真实生成能力 **且** 用户要求出图/出片 | 只要提示词包（降级为方案档） |
| 锐 | 有真实成片要修/要排版/要导出 | 只交付提示词包 |
| 诺 | 有上线数据，或用户问「为什么卖不动」 | 尚未上架 |

**必出场四人**：凯（调度）、凌（策略）、文迪（文案）、薇（终审）。这四人构成最低质量保障——没有调度的链路会停摆，没有策略的图会跑偏，没有文案的图不会卖，没有终审的图会带着错误上架。

## 七、单 agent 串行的四条提醒

1. **不要为了省事合并阶段** —— 阶段 2 的确认门在串行模式下依然要在对话中展示并等用户确认，不能自己确认自己
2. **不要在一个回答里同时出策略和成品** —— 串行模式下最容易犯的错是一口气从阶段 0 做到阶段 8，用户失去了在关键节点纠偏的机会
3. **角色切换时显式说明** —— 用「现在进入阶段 4，由伊万执笔」这类过渡，让产出边界清晰、便于用户按阶段回溯
4. **等用户时不空转** —— 等待确认期间，把不依赖该门禁的活先做了（视频脚本、排版规格、数据记录表），用户一确认就能接上；卡住时给出「你只需做一个动作，我就能继续下一步」

## 八、常见团队级失败

| 症状 | 病根 | 纠正 |
|---|---|---|
| 做出来的图很美但不像这个商品 | 跳过凌的 Style Lock，或雷没标素材角色 | 回到阶段 0 锁 Style Lock |
| 文案越写越满 | 无人守合规，或下游自行润色 | 逐字冻结 + 退回制度 |
| 十张图全部重做 | 薇/伊万为了统一而整批重跑 | 只补失败槽位 |
| 交付物一堆文件但没法上架 | 缺锐的规格导出环节 | 补阶段 7 |
| 团队自说自话，用户没参与 | 门禁做成内部仪式 | 确认门必须在**对话中**展示 |
| 主理人自己把活干完了 | 串行模式退化成代写 | 显式说明当前阶段与角色 |
| **等用户确认时全员空转** | 无人调度 | 凯把不依赖该门禁的阶段全部推起来 |
| **卡住了只说「做不了」** | 无人推流程 | 给最小可继续步骤：「你只需做一个动作，我就能继续下一步」 |
| **同一阶段改三版还没过** | 无人控节奏 | 停下问清诉求，不继续加码 |
| **成员间来回拉扯没结论** | 无人仲裁 | 凯按优先级当场裁定，或升级麦琪问用户 |
| **两个人各建一份账本/台账** | 工具未统一分配 | 凯统一到同一项目目录 |
| **有人绕过雷直接调生图工具** | 调度权旁落 | 全部经雷，台账才不脱节 |
