# 组装细则

模板是骨架，组装才是手艺。这份文件解决"照着模板填空却出来一堆废话"的问题。

## 一、字段是活的，不是固定的七件套

25 套模板共出现 **70 多个不同字段名**。不要拿某套模板的字段去套另一套。

高频字段（跨模板复用）：

| 字段 | 含义 | 写作要求 |
|---|---|---|
| `type` | 画面类型 | 每套都有，照抄模板值 |
| `subject` | 主体 | 产品名 + 材质 + 关键形态，写成名词短语 |
| `background` | 背景 | 说清是纯色、渐变、空间还是环境 |
| `lighting` | 布光 | **必须带方向 + 质感**（侧逆光 / 柔光箱 / 硬闪光） |
| `composition` | 构图 | 机位 + 景别（正面平视、45° 俯拍、中景） |
| `quality` | 技术规格 | 模板里已给，别改写成"最高质量"这种空话 |
| `style` | 摄影风格 | 手机随拍 / 编辑部大片 / 商业棚拍 |
| `environment` | 环境 | 真实空间描述，越具体越不 AI |
| `imperfection` | 瑕疵 | 反 AI 场景专用：噪点、手抖、偏色 |
| `layout` | 版式 | 信息图 / 拆解图专用：分区与层级 |
| `category_note` | 品类要点 | 从 `category_tips` 来的补充说明，**追加不替换** |

低频但关键的字段（如 `before_state`/`after_state`、`dimensions`/`steps`、`ui_overlay`、`season`）只在对应场景出现——**模板有才写，没有不加**。

## 二、变量填充

- `{product_description}` → 产品名 + 材质 + 形态，例："磨砂玻璃精华瓶，30ml，哑光白泵头"
- `{color}` / `{brand_colors}` → 用户给的具体色，没有就删该字段，不写 `{color}`
- `{feature_list}` / `{data_elements}` → 用用户真实卖点；**没有就留默认值的通用描述，不编数据**
- 填充后**逐个检查残留的 `{}`**——留着花括号会让模型把占位符当内容画出来

## 三、变体的真实分布（别假设每个模板都有四个）

- 每套模板有 **3–4 个**变体，不是统一 4 个
- 同名变体在不同场景含义不同：`luxury` 在 4 套模板里都有，但覆盖的字段各异；`minimal` 出现 3 次、`editorial` 2 次、`unboxing` 2 次
- **只应用用户选中或你推荐的那一个**；两个变体叠加会互相覆盖，得到四不像
- 变体只覆盖 `overrides` 里列出的字段，其余字段保持不变

推荐变体的判断依据：

| 品类/诉求 | 推荐 | 理由 |
|---|---|---|
| 高客单、礼赠 | `luxury` | 伦勃朗光 + 渐变暗底，质感立住 |
| 护肤、食品、母婴 | `fresh` | 亮自然光 + 浅粉调，降低距离感 |
| 3C、数码、SaaS | `tech` | 硬侧光 + 暗底极简，突出工艺与屏幕 |
| 需要跟品牌色走 | `color` | 把背景换成品牌色渐变 |

## 四、品类键对不上时怎么办

`category_tips` 的键**并不统一**：多数模板用通用七类（`beauty`/`electronics`/`food`/`fashion`/`home`/`jewelry`/`sports`），但也有模板写的是细分键（`skincare`、`fragrance`、`wine`、`coffee_shop`、`saas`、`running_shoes`…）。

处理顺序：

1. 先看**这个模板**实际有哪些键（读 JSON 时看 `category_tips` 的 key）
2. 精确命中就用
3. 没命中就用同模板里**最接近的上位类**（香水→`beauty`，跑鞋→`sports`/`fashion`）
4. 模板完全没有相关键 → 不写品类说明，或写一句自己判断的通用要点并**标注这是补充、非模板原文**

不要因为缺键就换成另一套模板——场景对了比品类说明更重要。

## 五、精简：删什么、留什么

**删**：空字符串、null、空数组、模板元数据（`id`/`name`/`keywords`/`examples`/`defaults`）、重复语义的字段（同时有 `background` 和 `environment` 时只留更具体的那个，除非两者确指不同事物）

**留**：光照、构图、背景这三要素永远留；有 `imperfection` 的场景别为了"干净"删掉它——它是反 AI 的关键

**合并**：同类信息合并成一句自然语言，例：
- 不要：`"background": "white", "surface": "white", "setting": "white studio"`
- 要：`"background": "pure white seamless studio background"`

## 六、六个常见组装错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 把所有字段都填满 | 约束打架，模型顾此失彼 | 只留有必要值的字段 |
| 堆关键词不写句子 | 现代模型更懂描述性句子 | 用自然语言短句 |
| 光照只写"good lighting" | 等于没写 | 方向 + 质感 + 软硬 |
| 材质不写 | 出来是塑料感 | 磨砂/拉丝/哑光/织物写清楚 |
| 反 AI 场景写成"完美真实" | 反而是 AI 味 | 写瑕疵、写机型、写 `NOT AI-generated` |
| 一次给三个变体让用户选 | 用户无从判断 | 推荐一个 + 说明理由 + 列出备选名 |

## 七、交付前自检

- [ ] 三要素齐（光照 / 构图 / 背景）
- [ ] 没有残留 `{}` 占位符
- [ ] 只应用了一个变体
- [ ] 品类说明是追加不是替换
- [ ] 反 AI 场景已过清单、无禁用词
- [ ] 含文字场景已提示后期叠加
- [ ] JSON 能直接被粘走，没有多余解释混在里面
