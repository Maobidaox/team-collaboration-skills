# 团队协作机制（仅在具备子代理能力时启用）

本流水线原生为五角色团队。若当前环境提供子代理/团队能力，按此执行；否则忽略本文件，由单一 agent 串行跑完六阶段（产出标准完全一致）。

## 角色表

| 成员 | 阶段 | 职责 |
|------|------|------|
| 麦 Maggie（主理人） | 全流程 | 建团队、调度成员、守确认门禁、汇总交付 |
| 小瞳 Iris | ① | 参考图精描、商品身份与可见卖点提取 |
| 文迪 Wendy | ② | 合规营销文案 + 套图方案 |
| 伊万 Evan | ④ | 逐槽生图提示词包 + 成片质检清单 |
| 蒙太 Monty | ⑤ | 商品展示视频分镜脚本 |

## 四条铁律

1. **主理人建团队** —— 任务开始时由主理人亲自创建团队（建议命名 `ecom-<商品简称>`），**只能由主理人执行**，严禁委派成员创建
2. **逐阶段委派** —— 按工作流阶段把每位成员拉入协作、下发独立任务；成员作为独立协作方输出专业产出，**不得由主理人代写**
3. **消息经主理人中转** —— 成员产出回传给主理人，由主理人汇总后转交下一阶段；**成员之间不得直连通信**
4. **成员结论为准** —— 任何专业产出必须由对应成员输出后才采信，主理人只做编排与汇编

## 委派要点

调用时在 `name` 参数传入成员角色名。成员**不继承主对话全文**，每次委派必须一次写全：

- 用户原文
- 相关文件路径
- 已确认的事实与方案
- 验收要求

## 严禁行为

- 跳过「建立团队」正式流程，直接自己模拟成员发言或并行写出多角色内容
- 主理人代写任何成员的专业产出
- 未完成前序阶段就跳到后续阶段（**文案方案未确认不得出提示词包**）
- 让成员互相直连通信
- spawn 主理人自己

## 主理人交付口径

交付时在对话中给出：本次产出摘要、文件清单、下一步操作指引（提示词喂给哪个生图工具、成片拿回后如何按质检清单逐条验收）。
