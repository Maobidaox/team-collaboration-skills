# 交付归档（阶段 9）

终审通过后，由主理人打包归档。目标是**用户拿到就能上架，下次能接着改**。

## 一、目录结构（固定）

```
<商品简称>-visual-v<版本>/
├── 00-strategy/        策略与证据账本（凌）
│   ├── 00-visual-strategy.md
│   └── claims.json    证据账本快照
├── 01-brief/          商品简报（小瞳）
├── 02-copy/           确认文案 + 套图方案（文迪）
├── 03-prompts/        逐槽提示词包 + 25 套模板引用记录（伊万）
├── 04-video/          视频脚本 + 成片 + 封面（蒙太/雷）
├── 05-retouch/        精修排版说明 + 成品（锐）
├── 06-qa/             终审报告（薇）
├── 07-data/           数据复盘（诺，按需）
└── assets/
    ├── main/          主图（按平台分目录）
    ├── detail/        详情页切片（编号有序）
    ├── video/         成片与封面
    └── source/        分层源文件（有则留）
```

## 二、命名规则

```
<商品简称>_<平台>_<用途>_<序号>_<宽x高>.<格式>

serum_tmall_hero_01_800x800.jpg
serum_amazon_main_01_2000x2000.jpg
serum_tmall_detail_03_750x1200.jpg
```

- 序号两位（`_01` 不是 `_1`），保证排序
- 详情页切片序号即排版顺序
- 版本走语义号 `v1.0` / `v1.1`，文件名不含版本，版本由目录区分

## 三、交付清单（四段式，主理人照此汇报）

```
① 本次产出摘要
   做了什么、到了哪一环节、版本 v____

② 文件清单
   带路径，按九阶段顺序

③ 下一步操作指引
   - 提示词喂给哪个生图工具、怎么喂
   - 成片拿回后按哪份清单验收
   - 成品怎么上传（平台、顺序、注意事项）

④ 状态分级
   ├── 已完成：______
   ├── 待处理：______
   ├── 被阻塞：______（含阻塞原因 + 最小可继续步骤）
   └── 未执行：______（能力不支持时标 unsupported）
```

**状态分级必须分开讲。** 把「已完成」和「待处理」混在一起，用户会以为全部做完了。

## 四、归档时必带的四件（缺一件，下次就得重问）

1. **证据账本快照**（`claims.json`）—— 哪句是已确认、哪句待补证，下次直接继承
2. **已确认文案原文** —— 逐字冻结的依据，下游改字要有比对基准
3. **Style Lock** —— 九项锁死项，下个版本必须沿用
4. **终审报告与退回记录** —— 哪些问题修过，避免重复踩坑

## 五、常见缺项检查

- [ ] 缺白底图（Amazon/多平台必备）
- [ ] 缺视频封面（首帧单独导出）
- [ ] 详情页切片未编号
- [ ] 字体授权未标注
- [ ] 平台规则未标注「需复核」
- [ ] 源文件未留存（后续改字改图会很难）
- [ ] 交付清单没写「被阻塞」和「未执行」

## 六、版本迭代继承规则

下一版做之前，先读上一版的归档，继承三件事：

| 继承 | 不继承 |
|---|---|
| Style Lock 九项 | 具体构图（允许按驱动力调整） |
| 证据账本（已确认条目） | 待补证条目（需重新验证） |
| 目标平台与规格 | 上一版的裁剪尺寸（平台规则可能已变） |

**文案不自动继承**：上一版确认过的文案，在新任务里仍需重新过合规门与确认门。
