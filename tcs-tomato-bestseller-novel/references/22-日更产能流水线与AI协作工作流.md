# 22 · 日更产能流水线与 AI 协作工作流（口径：2026-09）

> 职业作者的核心竞争力是**单位时间的稳定产出**。
> 本文件给出一条可复制的日更流水线。

---

## 一、日更流水线（五段式）

```
① 前置：细纲就绪（前 30 章）
     ↓
② 起草：本章事件卡（3 分钟，写下目标/事件/钩子/爽点）
     ↓
③ 成稿：正文 2000–2400 字（核心时段，专注 60–90 分钟）
     ↓
④ 自检：节奏 + AI 味 + 钩子（10 分钟）
     ↓
⑤ 归档：更新台账（人物/伏笔/时间线）
```

**关键**：把「想」和「写」分开。想的时候不写，写的时候不想。

## 二、产能基准（参考）

| 水平 | 日更字数 | 单章耗时 | 备注 |
|---|---|---|---|
| 新人 | 2000–4000 | 2–3 小时 | 先求稳定不求快 |
| 熟练 | 4000–6000 | 2–3 小时 | 细纲先行是提速关键 |
| 职业 | 6000–10000 | 3–4 小时 | 依赖存稿与流水线 |
| 顶尖 | 10000+ | —— | 通常有团队或长期存稿池 |

## 三、AI 协作的正确分工

| 环节 | AI 负责 | 人负责 |
|---|---|---|
| 选题 | 提供赛道数据与趋势 | 最终决策 |
| 大纲 | 结构节拍建议 | 核心冲突与终局 |
| 开头 | 给出 5 个开局候选 | 选定并重写 |
| 正文 | 场景草稿 / 对话草稿 | **语言、节奏、细节、金句全部重写** |
| 钩子 | 批量候选钩子 | 选择并改写成自己的语言 |
| 自检 | 节奏/AI 味/一致性诊断 | 判断是否采纳 |
| 台账 | 提取人物与伏笔 | 核对与维护 |

**红线**：AI 生成的正文**必须经过人类改写**才能发布（AI 味重 = 低质判定风险）。

## 四、六类提示词工程模板

### 1. 选题分析提示词
```
角色：你是番茄网文赛道分析师。
任务：基于【当前季度】番茄平台数据，分析【赛道名】的竞争度与突围机会。
输出：① 赛道在榜作品特征聚类 ② 3 个差异化切入角度 ③ 每条的风险与受众
约束：结论须标注依据；不确定的标「待核实」。
```

### 2. 大纲生成提示词
```
角色：你是网文结构工程师。
输入：赛道【X】、核心钩子【Y】、主角目标【Z】。
任务：输出 5 卷分卷大纲 + 前 30 章逐章细纲。
每章必须包含：事件、转折、爽点类型、章末钩子类型。
```

### 3. 开篇生成提示词
```
任务：为【书名】写第 1 章前 200 字。
要求：① 第一句必须是人物的动作或对话 ② 100 字内出现异常事件
③ 不出现世界观说明 ④ 结尾留一个钩子
```

### 4. 正文续写提示词
```
输入：本章事件卡 + 上一章结尾 + 人物台账摘要。
任务：写本章正文 2000–2400 字。
要求：① 每 300 字一个新信息或新动作 ② 至少 1 个爽点
③ 对话不超过 30 字/句 ④ 章末用【钩子类型】收尾
```

### 5. 去 AI 味提示词
```
任务：把下面的文字改写为人类写作质感。
规则：① 把情绪结论换成动作/身体反应 ② 打散整齐句式
③ 加入 1 处口语/断句 ④ 参数：句长标准差提高、段落长度参差
```

### 6. 数据诊断提示词
```
输入：作品数据（首章完读/三章留存/追读率/时长）。
任务：按六数诊断法归因，输出主因 + 30 天行动清单。
约束：只给可执行动作，不给「多写多练」这类废话。
```

## 六、本章速查卡

- **想和写分开** —— 提速第一原则。
- **细纲先行** —— 30 章细纲是产能的地基。
- **AI 出结构，人出语言** —— 这条不守住，质量必崩。
