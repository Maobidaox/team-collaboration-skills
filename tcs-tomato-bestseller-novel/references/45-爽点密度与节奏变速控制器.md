# 45 · 爽点密度与节奏变速控制器（v2 新增）

> **口径日期：2026-09-11** ｜ 2026 年算法**完读率 <15% 或追读率 <35% 直接停推荐**。爽点密度 = 完读率的物理基础。本节给出一套"可调节"的爽点密度标准。

## 一、爽点密度四级标准（按章节类型）

| 章节类型 | 爽点密度 | 说明 |
|---|---|---|
| **开篇（1–10 章）** | **每章 2–3 个** | 留存生死期，密度必须拉满 |
| **上升期（11–50 章）** | 每章 1–2 个 | 稳定输出 |
| **高潮期（51–80 章）** | 每章 2 个 + 每 10 章 1 大高潮 | 情绪轰炸 |
| **长尾期（80 章+）** | 每章 ≥1 个 | 防疲软 |

**铁律：连续 2 章无爽点 → 追读必掉。**

## 三、"爽点密度控制器"三档调节（按数据反馈）

### 档位一 · 提速档（数据下滑时用）

```
动作：把"3 章一爽点"改成"每章一爽点"
手法：
  · 删掉过渡章节（把铺垫并进冲突章）
  · 把"将要发生"改成"当场发生"
  · 缩短憋屈期（从 3 章压到 1 章）
  · 增加"群体反应"配菜（低成本高密度）
```

### 档位二 · 标配档（数据稳定时用）

```
动作：维持"每章 1-2 个爽点 + 每 30 章 1 大高潮"
手法：A 线推进 + B 线情绪 + C 线钩子三线交错
```

### 档位三 · 蓄爆档（准备大高潮时用）

```
动作：短暂降密（1-2 章），为下一章的大爆发蓄势
手法：
  · 制造"绝境"（情绪压到最低）
  · 埋"翻盘要素"（读者隐约察觉但不确定）
  · 然后一次性释放（回收 2-3 个伏笔 + 大爽点）
⚠️ 蓄爆期 ≤2 章，超了读者会跑
```

## 四、节奏变速的四种手法（让"平"的地方动起来）

| 手法 | 做法 | 效果 |
|---|---|---|
| **句长变速** | 长句 3 个必跟 1 个短句 | 阅读节奏有跳感 |
| **段落变速** | 长短段交替（最长段 ≤200 字） | 视觉不疲劳 |
| **场景变速** | 每 1–2 章切一次场景 | 避免单调 |
| **信息变速** | 每 300 字一个新信息 | 停留时长↑ |

## 五、爽点密度自检（交付前）

```bash
# 节奏曲线六维诊断 + 爽点分布
python rhythm_analyzer.py --file 稿件.md --curve

# 钩子密度扫描
python hook_density.py --file 稿件.md --mode 全篇

# 质检打分
python quality_selfcheck.py --file 稿件.md --prompt-out 优化提示词.md
```

**判定线**：
- 连续 2 章无爽点 → **重写**；
- 10 章内无大高潮 → **补高潮**；
- 憋屈期 >3 章 → **压缩**。

## 六、三类"伪爽点"（要避开）

| 伪爽点 | 为什么无效 |
|---|---|
| **自嗨型** | 主角自己觉得爽，读者没有代入 |
| **无对手型** | 敌人太弱，赢了没成就感 |
| **延迟型** | 憋了 5 章才反击，读者早跑了 |

⇒ **真爽点 = 读者期待 × 意外程度 × 兑现速度**。

## 七、一句话总结

**完读率不是靠"文笔好"，是靠"每 300 字有东西看"。** 把爽点密度当成技术指标来管理，而不是灵感。
